# LOD Explanation Pipeline

This folder generates explanations for recommendation lists using Linked Open Data (LOD) item properties and then
computes explanation diversity metrics.

The current pipeline does not train recommenders and does not reorder recommendation lists. It receives recommendation
outputs that were already generated by recommender algorithms, explains the top recommended items for each test user,
and saves both the explanations and their metrics.

## Entry Point

Run the pipeline from this folder:

```powershell
python run_LOD.py
```

`run_LOD.py` defines which recommendation outputs will be explained:

```python
explanation_configs = {
    "rec_algs": "BPRMF NCF UserKNN ItemKNN",
    "expl_alg": "explod",
    "n_explain": 10
}
```

- `rec_algs`: recommender outputs to explain.
- `expl_alg`: explanation algorithm. The implemented path currently used is `explod`.
- `n_explain`: number of recommended items explained per user.

## Inputs

The pipeline expects these files relative to this folder:

- `../datasets/recommender_train_test_oficial/train.csv`: user-item interactions used as the user history.
- `../datasets/explanation_raw_files/user_split_train_val_test/test_users.csv`: users selected for explanation.
- `../datasets/knowledge-graphs/props_wikidata_movielens_small.csv`: movie properties extracted from Wikidata.
- `../datasets/recommendation_files/recommendation_lists/.../optimized_*_K=20_recs.csv`: recommendation lists generated by each recommender algorithm.

The recommendation files are expected to contain rows in this format:

```text
user_id,item_id,score
```

The Wikidata property file is read with these columns:

```text
movieId,title,prop,obj
```

where `obj` is the semantic entity used in the explanations, such as an actor, director, genre, award, or another KG
attribute.

## Pipeline Steps

1. `run_LOD.py` maps the selected recommender names to their recommendation CSV files.
2. It loads the test users and creates one `LODExplanationGenerator` for each recommendation file.
3. `LODPersonalizedReordering` loads the training interactions, recommendation list, and Wikidata properties.
4. The training and recommendation data are filtered to keep only the selected test users.
5. For each user, the generator retrieves the user's historical items ordered by timestamp.
6. A semantic profile is computed from the user's historical items.
7. For each recommended item, the generator finds KG entities shared by the recommended item and the user's historical items.
8. Among the shared entities, it selects the entity or entities with the highest score in the user's semantic profile.
9. It writes an explanation path connecting historical items to the recommended item through those shared semantic entities.
10. After all users are processed, it computes individual and aggregate explanation metrics.

## Semantic Profile

The semantic profile scores KG entities according to how representative they are for a user. For each entity in the
user's historical items, the score is:

```text
(npi / i) * log(N / dft)
```

- `npi`: number of times the entity appears in the user's historical items.
- `i`: number of items in the user's history.
- `N`: total number of items in the KG property set.
- `dft`: number of items in the KG property set that contain this entity.

This gives higher scores to entities that appear often in the user's history but are not too common across the whole
catalog.

## Explanation Format

For each user, the output includes:

- Items previously interacted with by the user.
- The top semantic attributes in the user's profile.
- The recommended items being explained.
- Explanation paths for each recommended item.

Each explanation path has this structure:

```text
"Historical Movie 1"; "Historical Movie 2" nodes: "Shared KG Entity" destination: "Recommended Movie"
```

In other words: the recommendation is explained by showing that the recommended movie shares important KG attributes
with movies the user previously interacted with.

## Metrics

The pipeline computes:

- Mean and standard deviation of historical item diversity used in explanations.
- Mean and standard deviation of KG property diversity used in explanations.
- Total aggregate diversity of historical items.
- Total aggregate diversity of KG properties.
- `ETD`: Explanation Type Diversity.
- `SEP`: Shared Entity Popularity.

`ETD` measures how many distinct explanation entities are used relative to the number of recommendations being
explained.

`SEP` measures the popularity of the shared entities used in the explanations. It uses memoization while processing
users to avoid recomputing the same property popularity tables repeatedly.

## Outputs

Generated files are saved under:

- `../datasets/lod_results/output/`: full textual explanations.
- `../datasets/lod_results/individual_metrics/`: per-user `sep` and `etd` values.
- `../datasets/lod_results/average_metrics/`: aggregate metrics for each recommender output.

For example, explaining BPRMF recommendations creates:

```text
../datasets/lod_results/output/output_explanations_optimized_bprmf_K=20_recs.csv
../datasets/lod_results/individual_metrics/indiv_metrics_explanations_optimized_bprmf_K=20_recs.csv
../datasets/lod_results/average_metrics/avg_metrics_explanations_optimized_bprmf_K=20_recs.csv
```

## Main Files

- `run_LOD.py`: selects recommendation files and starts the explanation pipeline.
- `lod_explanation_generator.py`: generates ExpLOD-style explanations and stores individual metrics.
- `lod_reordering.py`: loads data and builds user semantic profiles from LOD/KG properties.
- `evaluation_utils.py`: computes aggregate explanation metrics.
